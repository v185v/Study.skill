# 原课程修订与进度核对

## 修改入口

用户提出追加、扩写、删减、纠错、换个讲法、重写、去 AI 味、调整章节顺序或重组课程时，直接修改原课程。无需再要求用户说“修改原文”，也无需再次确认这项已提出的修改。普通知识问答可以直接回答；要求把讲解、练习或纠错纳入课程时，写入对应正文。

- 讲解、例子、推导放到原小节中合适的位置，调整上下文衔接。
- 删减和重写直接作用于原文件，去 AI 味时读取 `anti-ai-writing.md` 和对应语言指南，保留事实、术语和来源。
- 新练习放入相关原小节；整套练习卷可作为原课程中合理位置的新小节。改变了结构就同步更新大纲和前言。
- 不再生成固定“内容补充”章节，不把新增内容默认放在末尾，不创建另一套平行课程。
- 已有旧补充文件不自动删除。修改这些内容时按主题并入对应原章节，核对旧路径和学习记录；无关旧文件保留，待用户实际要求涉及它们时再整理。

## 修订流程

1. 读取原课程、大纲、`meta.json`、`domain-tree.json`、`concepts.json`、`params.json`，以及存在的 `learning-record.json`、`free-learning-record.json` 和 `progress-review.json`。只修改用户要求的范围，保留未涉及内容。读取这些文件是为了保留真实进度，不能凭聊天记忆重建。
2. 修改前保存受影响文件和状态的副本到课程状态目录的 `revision-backups/{revision_id}/`，保留可追溯的原路径；这是修订恢复材料，不在播放器目录里展示。无歧义的小错别字/坏链接修复不要求整课备份。
3. 建立旧模块/小节到新模块/小节的对应关系。按内容、学习目标和题目核对，不能只靠同名、编号相同或“第几章”判断。只改顺序尽量保留目录 ID；必须改名时明确一对一映射。
4. 完成原课程修改，同步更新课程概览、`syllabus.md`、模块前言、图像路径和先修关系。校验本次修改的讲解、练习和引用；结构大改时做受影响学习链路的贯通检查。扩写和新增课程单元仍遵守课程规模与课件质量规则。
5. 按下文保留可对应的进度，将需要用户决定的部分写入 `progress-review.json`。课程修订完成可以交付；待确认进度不会阻塞其他章节或自由浏览。
6. 报告已改内容，列出受影响章节的原/新位置、原进度、改动原因、哪些已保留、哪些待选择。用户有待选择项时再询问，用户可以逐项或批量决定。不要为这份进度选择暂停尚未完成的课程修改。

修订期间不要让用户把旧页面的练习写回新题目。完成后提示刷新播放器；改过题意、选项或答案的练习使用新 ID，未改题目保持原 ID。不要把旧作答套到新题上。

## 哪些进度保留，哪些交给用户

| 改动 | 进度处理 |
| --- | --- |
| 未修改章节、小节或题目 | 原样保留 |
| 改名/移动/重新编号，内容和目标一一对应 | 映射保留位置、完成记录、作答和掌握状态，报告映射 |
| 仅去 AI 味、措辞润色、错别字/链接修正，目标与题目不变 | 保留进度，在改动清单中说明 |
| 拆分、合并、替换、删除，或新增要求使原完成状态不能直接代表新章节 | 保留旧状态快照，列出受影响部分为“待确认”，由用户决定 |
| 完全新增且没有任何旧进度对应的单元 | 按普通新内容初始化；若使已完成章节的完成结论发生变化，该章节仍需用户确认 |

在同一章内也按小节和题目保留：只改第 2 节，不清空第 1、3 节的进度。不因一次结构修订重置整门课。必须同时核对普通和自由学习记录，即使当前在自由模式，也不能破坏将来切回普通模式的进度。

一对一迁移时检查 `meta.current_module`、`completed_modules`，技能树节点 ID / `module` / `prerequisites`，概念所属模块，以及两份记录中 `current`、`pages`、`exercises`、`legacy_checkpoints`、`completions` 的 `module`、`section`、`content_file`。未改题目的 ID 和作答保留，`completions.exercise_ids` 要与题目映射一致。不要重复发放 XP、凭迁移生成作答或改写真实复习历史。

不确定的旧状态留在原文件和备份中，使用下面的待确认清单隔离显示；不要先把它们全改成“未学习”再问用户。已删除目标的旧记录也不能悄悄删掉。未答复项持续待确认；只影响这些目标的完成/掌握结论，不阻止其他章节学习。

## 待确认清单

课程状态目录的 `progress-review.json` 是 schema 5 的可选扩展。仅出现进度冲突时创建，使用 `write-state.py` 原子写入。播放器会读取并显示未解决项，同时不把待确认目标的旧完成/作答当成新内容已完成。格式定义在 `state-schema.md`。

每项记录旧位置、旧状态、修改原因和新目标。`decision: null` 表示未选择；待确认期间不要填默认答案。已有未解决项应合并维护，不覆盖丢失。

给用户的清单示例：

| 编号 | 原章节与进度 | 修订后 | 需要决定的原因 |
| --- | --- | --- | --- |
| R1 | 链表反转：已掌握；自由学习已读 | 拆为迭代反转、递归反转 | 原进度无法直接分配到两个目标 |
| R2 | 图的存储：学习中 40% | 合并为图的表示与遍历 | 新章节增加了遍历要求 |

可用选择：“保留原进度”“设为未学习”“设为学习中（可指定百分比）”“设为已读/已掌握”“删除项仅归档”“暂不决定”。拆分/合并时允许用户分别指定新目标和两种学习方式的状态；不为未提及的目标或模式推断答案。

用户决定后，再将选择落实到对应 `meta.json`、节点和两份记录。未学习只清除选定目标的有效完成/掌握结论，历史证据保留在备份中；学习中保留仍有效的原始作答；已读只更新页面记录，不自动变为 mastered。用户明确选择“已掌握”可恢复/设置章节状态，并记录为用户在修订后的确认，不伪造正确作答、评分或新增 XP。被删除内容默认保留为历史材料，只有用户明确选择归档后才移出活跃进度；保留归档快照。

写入选择后将该项 `decision` 设为用户选择的说明（可记录逐目标逐模式选择），加 `decided_at`。未选择项继续 `null`。确认进度时，核对旧题是否仍存在，不能因为用户选择保留进度就把已删除题目的旧答案挂到新题上。参考对齐规则更新先修解锁；保留未受影响节点状态。自由/普通切换仍保留各自记录，最终使用修订后的有效结构。
